# RailGuard interface

The user chose the **Night Glass** preview (concept C) on 18 September 2026, then requested richer colour, connected 3D and AI investigation, visible upload controls and more detailed engineering geometry on 19 September. The current layout uses a resizable floating AI modal over a blurred backdrop and one selectable signal chart beneath the 3D evidence. Midnight, indigo and violet surfaces, cyan actions, restrained pink accents and readable glass annotations connect the interface. Visual styling does not change prediction values; model evaluations are documented separately.

## Visual rules

- Page `#0B1021`, indigo/violet panel gradients, cyan selection and lavender context accents define the shared palette. Text stays light, and model findings retain amber emphasis. Task cards and subsystem icons have distinct identity accents, not condition scores.
- `frontend/src/components/workspace/vivid-theme.css` supplies the colour layer over the earlier Night Glass and gradient styles. It gives navigation, cards, controls, evidence and 3D one palette, with sufficient specificity for dynamically loaded components. `investigation-workbench.css` supplies workspace structure; the floating window and shared telemetry chart have their own component styles.
- Use glass selectively on navigation and annotations; result and evidence surfaces stay opaque enough to read. Primary buttons have dark text on a cyan-to-periwinkle gradient. Selected controls also use text and borders.
- Amber identifies a supported model finding to review. It is not a verified-fault or calibrated-severity scale. Missing evidence stays neutral and explicitly labelled.
- Shared telemetry charts use cyan, teal and lavender series colours, clear source units and low-opacity area fills. Solid measured runs are distinct from the subdued dashed gap bridges in the default Continuous display; Preserve gaps removes the bridges. Colour does not imply a probability or safe/unsafe threshold. The optional network map retains grayscale basemap tiles and identifying rail-line colours, without fabricated train positions.
- Text labels accompany icons, keyboard focus is bright cyan, and reduced-transparency preferences remove glass blur. Reduced-motion preferences disable decorative transitions. Phone navigation supports Escape and keyboard focus management. Tables scroll inside their containers.

## Main workflow

1. **Overview:** choose Door, Air conditioning, Rail corrugation or Structural health. Recent analyses provide a direct route back to saved results. The optional map expands below these tasks.
2. **Analyse data:** upload inputs are visible at the top, with system selection, file-format guidance and bundled Test examples. Saved-run and recording selectors stay visible above a compact reference to the required PS3 output, official metric and export filename. A completed file leads with its main result before supporting detail. Switch between Current file and All files to compare a run. The 3D finding is followed by measurements, sources and one chart with a Signal dropdown. Exact CSV rows remain visible in a bounded table with pagination; saved history follows the results.
3. **3D + AI investigation:** one navigation item opens the selected component and its evidence. Measurements and one selected-signal chart sit directly below the scene. Ask AI opens a resizable floating modal on the right, with the same recording context; its launcher is available on every workspace view while the window is closed. The selected-component shortcut prepares a current-file question for review and submission. Project scope remains available without a completed run. Legacy `/?view=twin` opens this connected view at `/?view=investigation`.
4. **Model performance:** inspect saved-model local validation, candidate comparisons and evaluation limits.
5. **Export results:** choose completed runs and check the recordings to include. The preview shows the exact CSV files and row counts before download.

Overview shows each required output and the current model's measured local-validation metric; it does not calculate an aggregate accuracy or official score. Limitations and data provenance remain in technical sections. Preparing a component question does not make a paid AI request; the user can edit it before sending.

## Floating investigation

`InvestigationWindow.tsx` presents the agent as a modal dialog. A blurred, dimmed backdrop covers the workspace, background controls are inert, page scrolling is locked and keyboard focus stays inside the open window. It replaces the earlier inline and wide-screen agent columns. The compact composer stays at the bottom; scope controls, selected-component context, task starters, conversation and cited sources remain accessible inside the window.

The floating launcher hides while the modal is open. The header Close button, Escape or a backdrop click hides the window and restores focus to its opener when available. Ask AI reopens it. The window stays mounted after its first opening, preserving its draft, chosen size and any request already running. Reopening it does not automatically send or repeat a question.

All four edges and four corners support pointer resizing. Four labelled edge buttons provide keyboard resizing along their corresponding axis: arrow keys move the edge by 16 pixels; Shift changes the step to 48 pixels. A nominal 340 × 360-pixel minimum adapts to smaller viewports, and clamping retains 12-pixel screen margins. Header Maximise and Restore controls switch between the available viewport area and the previous size. The retained dimensions survive closing and reopening while the workspace remains mounted; resizing does not change recording or investigation state.

## Finding-focused 3D

The combined investigation opens around the selected recording's result. **Focus result** restores that focus; **Review first** links each supported finding to its measurements. Door highlights describe detected actions, ACV uses a lifted cooling-unit view for the ranked car, and Rail opens a paired-rail view with the predicted side highlighted. Car layout and eight-car views remain available for context. Structural damage remains a recording-level estimate on a neutral test assembly.

Amber highlights mean a model finding to review, not verified criticality. ACV unit geometry is illustrative; no particular unit is diagnosed. Complete measurements and sources remain visible, and every returned signal is available through the chart's Signal selector. Missing evidence stays explicitly unavailable. Scene overlays use concise engineering labels; the lower Method & interpretation section states geometry and inference scope. The scene and surrounding interface share the same indigo/cyan palette.

## Geometry and data

`RailTrackScene.tsx` builds profiled steel rails, polished running surfaces, concrete sleepers, fasteners and deterministic instanced ballast. Its decorative surface grain is generated locally; it is not telemetry or reconstructed defect geometry. Amber is a display overlay on the predicted side. `CoolingUnit.tsx` batches roof equipment with fan guards, condenser fins, service panels, fasteners, seals and mounting details. `EngineeringAssemblies.tsx` batches Door glazing, guides, rollers, belt drive and motor by material; its SHM assembly adds I-section beams, bracing, bolted joints, deck panels and supports. These details improve illustrative geometry rather than claiming an identified physical asset or fault location.

Cool-white lighting and restrained cyan/violet reflections bring out neutral metallic materials. Lighting, shadows and camera framing are shared across the component views. A transparent shadow receiver grounds each component over a continuous blue/indigo CSS studio gradient; an opaque lit floor no longer creates a gray horizon or rectangular colour break. Scene geometry and its material groups are reused within their component lifetime and disposed on unmount.

The current-file result embeds one canvas only. Switching to All files, Evidence or Validation unmounts it. Rendering occurs on demand. A compact inspector shows the selected result and two key measurements. Complete measurements, sources and a single signal chart fill responsive sections below the scene; long evidence lists cannot stretch the model column into an empty panel. The top-right Signal dropdown shows the selected index and available count and keeps the preferred signal type across ACV car or Rail side changes where a matching trace exists.

`TelemetryChart.tsx` serves both analysis and 3D evidence. Responsive axes retain source units and values, mouse movement selects an actual retained point, and a labelled keyboard-operated slider exposes the same point inspector. Continuous display is the default: solid lines show measured runs and subdued dashed links bridge their endpoints across source gaps for display only. Preserve gaps removes those links. No values are filled or added to the point inspector, statistics, evidence or model data. Controller states and commands use step lines within measured runs. Each chart distinguishes sampled or min/max-envelope previews and labels its minimum, maximum and mean as statistics of retained points, not the full waveform. Full-recording measurements remain in the evidence cards.

The chart content follows the PS3 task: Door electrical/motion/state channels; ACV cabin and cooling-target observations plus target/peer residuals; Rail representative side-level acceleration envelopes; SHM ordered stress against sample index. New Door reports can include all eight supported channels with finite values, and new ACV reports include additional target/residual previews. Existing saved reports retain their original evidence; generating the extra previews requires a new analysis. Source calibration, missing evidence, physical location and recording duration are never inferred merely to complete a chart.

The returned ACV ranking is preserved when evidence metadata is absent. Such cars display **No saved evidence** and the first car receives a neutral **evidence not recorded** description rather than an unsupported inspection recommendation.
